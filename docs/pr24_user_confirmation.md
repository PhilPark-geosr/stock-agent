# PR #24 사용자 확인 필요 결정

## 1. 이 문서의 용도

PR #24를 PR #27 로그인 기능과 연결하면서 제가 선택해 설계·구현한 정책과, 저장소만 보고 확정할 수 없어 남겨 둔 항목을 한곳에 모았다. 확인 결과를 이슈 #25 댓글에 기록하면 PR #24의 선택 근거가 명확해진다.

표의 **현재 권고**는 지금 구현된 방향이다. 바꾸기로 결정하면 관련 설계·테스트·구현을 함께 변경해야 한다.

## 4. PR 구성에 대해 제가 선택한 것

- 기존 PR #24와 PR #27 브랜치는 직접 수정하지 않는다.
- 별도 통합 PR을 만들고 **PR #27의 `26-design-login` 브랜치를 base**로 사용한다.
- 이 방식에서는 PR #27의 로그인 설계 문서가 diff에 포함되지 않고, PR #24 브리핑 설계·코드와 로그인 연동 변경만 보인다.
- PR #27이 소유한 OAuth state 처리, 로그인 시도 상태, 세션 발급, Electron 로그인·초기화 코드는 기준 커밋 `eb0af2c` 그대로 유지한다.
- 브리핑 API는 PR #27이 이미 제공하는 `get_current_account` 경계만 사용하며 로그인 구현 내부를 변경하지 않는다.
- 앞선 검토에서 발견한 OAuth state 선점·Electron 재초기화 문제는 이 PR에서 수정하지 않는다. 필요하면 PR #27 작성자와 합의한 별도 수정으로 다룬다.
