# PR #24 AI 투자 브리핑 설계·구현 감사

## 1. 감사 범위와 기준

이 문서는 PR #24의 AI 투자 브리핑 설계·구현과 PR #27 로그인 결과를 사용하는 연동 경계만 검토한다. PR #27의 로그인 설계 문서는 수정하거나 재평가하지 않았으며, 이 브랜치의 `design/login_feature_design.md`는 PR #27의 기준 커밋 `eb0af2c`와 동일하다.

검토 기준은 저장소 `AGENTS.md`의 설계 절대 규칙 11개, PR #24의 요구사항, 이슈 #25의 보완·선택 항목이다.

## 2. 최종 판정

| 구분 | 판정 | 근거 |
| --- | --- | --- |
| PR #24 OOA | **적합** | 사용자 목표, Essential Style, Black box, 정식 UC 명세와 외부 관찰 결과를 사용한다. |
| PR #24 OOD | **적합** | OOA 이후에 배치했고 모든 책임을 `FR-B01~12`로 추적한다. |
| 설계↔구현 | **PR #24 경로 일치** | 사용자 소유권, 공유 분석 참조, 부분 실패 재시도, 거래소 일정, 버전·범위 저장과 내부 실행 경계를 구현했다. PR #27의 기존 로그인·분석 코드는 변경하지 않는다. |
| 로그인 연동 | **현재 범위 일치** | 임시 `X-User-Id` 대신 PR #27 서비스 세션의 현재 계정으로 조회·생성 범위를 제한한다. |
| 외부 메시지 전달 | **의도적으로 보류** | 사용자별 `NotificationConnection`이 없으므로 전역 자격 증명으로 보내지 않고 전달을 차단한다. |
| PR #24 완료 조건 | **외부 확인·후속 작업 남음** | PR #23 종목 ID, 사용자 상태·시간대, 운영 DB·복구 훈련과 실제 배포 E2E가 남아 있다. |

테스트 통과는 저장소 안의 현재 구현 범위를 검증한다. 실제 카카오 계정, 운영 DB와 중앙 배포 환경까지 검증했다는 뜻은 아니다.

## 3. 설계 절대 규칙 판정

| 번호 | 판정 | PR #24 반영 내용 |
| --- | --- | --- |
| 1. 사용자 목표 | **적합** | `장 시작 전 투자 판단 확인`, `장 마감 후 당일 변화 확인`, `과거 브리핑 확인`으로 이름 붙였다. |
| 2. Essential Style | **적합** | OOA에서 화면, API, DB, 내부 ID와 프레임워크를 제거했다. |
| 3. Black box | **적합** | 기본 흐름은 사용자의 요청과 서비스가 제공하는 결과·오류만 표현한다. |
| 4. 간결한 UC 다이어그램 | **적합** | 개인 투자자와 세 사용자 목표만 표시하고 스케줄러를 액터에서 제외했다. |
| 5. 올바른 `include` | **적합** | 실행 순서를 나타내는 `include`를 사용하지 않는다. |
| 6. 다이어그램·명세 분리 | **적합** | 각 UC에 ID, 목적, 액터, 트리거, 사전조건, 기본·예외 흐름과 보장을 기록했다. |
| 7. 목표·기능 요구 분리 | **적합** | `@/#`, 구조화 종목 ID, API와 저장 계약은 FR/OOD에만 둔다. |
| 8. OOA 우선 | **적합** | 문서를 OOA → FR → OOD 순서로 구성했다. |
| 9. OOD 추적 | **적합** | 책임·저장·API 요소를 `FR-B01~12`에 연결했다. |
| 10. 시스템 경계 | **적합** | 사람만 OOA 액터로 두고 내부 스케줄러·저장소를 제외했다. |
| 11. 자체 검토 | **적합** | 문서 마지막에 교체 가능성, 관찰 가능성, 다이어그램과 추적 관계를 확인했다. |

## 6. 남은 위험과 후속 작업

1. PR #23 병합 뒤 정식 종목 ID·종목명 정렬·통합 테스트로 전환한다.
2. 사용자별 `NotificationConnection`, 전송 재시도 간격·최대 횟수와 최종 실패 가시성을 설계·구현한다.
3. PR #27 기준선의 `AnalysisResult.alert_sent_at`은 공유 분석에 남아 있다. PR #24 브리핑 경로는 이 필드를 읽거나 쓰지 않지만, 제거 여부는 PR #27 작성자와 합의한 별도 변경으로 다룬다.
4. 앞서 발견한 OAuth state 검증 순서와 Electron 초기화 실패 복구 문제는 PR #27 소유 코드이므로 이 PR에서 수정하지 않는다.
5. 활성·탈퇴 사용자 상태와 사용자 시간대 정책을 로그인 도메인 담당자와 확정한다.
6. 운영 DB 제품, 백업 위치·보존 기간·RPO/RTO를 정하고 복구 훈련을 수행한다.
7. 실제 카카오 계정, Redirect URI와 중앙 배포 URL을 사용하는 E2E를 수행한다.
8. 데이터 제공자가 장 마감 뒤 가격을 수정하는 실제 행태를 관찰하고 자동 재생성 정책을 다시 판단한다.
