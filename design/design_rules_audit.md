# 설계 절대규칙 적용 검토

2026-10-07 · 기준: 저장소 `AGENTS.md`의 11개 규칙 및 사용자 지침 “도메인 → 관계 중심 최초 시퀀스 → 상세 클래스”.

## 검토 범위와 결론

이번 대화에서 작성한 [검색 설계](stock_search_usage_design.md), [갱신 설계](security_catalog_refresh_design.md), 두 HTML 설명서와 기존 공통 설계·공유 그림을 검토했다. 저장소의 로그인·카카오·스케줄러 등 다른 작성 시점의 모든 설계서를 검토했다는 뜻은 아니다.

현재 기능 설계는 절대규칙을 적용하고 있다. 다만 재검토 전 설명서의 시퀀스에 중간 책임을 건너뛴 화살표와 최초 그림에 불필요한 커밋 표현이 있었고, 이전 참고본에 분리 전 갱신 책임과 오래된 확정 상태 문구가 남아 있었다. 이를 수정했다. 문서 작성·검토 완료와 모든 정책의 합의·구현 완료는 구별한다.

## 규칙별 근거

| 규칙 | 현재 근거·판정 |
| --- | --- |
| 1. 사용자 목표로 UC 명명 | 검색 2절은 관심종목 관리·알림 조건 설정·저장 브리핑 열람, 갱신 2절은 신뢰할 수 있는 기준정보 유지. 검색/클릭/저장을 독립 UC로 쪼개지 않음. |
| 2. Essential Style | UC 명세의 목표·기본 흐름은 특정 UI·API·DB를 교체해도 유지됨. 코드·키·주기는 FR/OOD에 별도 기록. |
| 3. Black box | UC에서 사용자/외부 제공자의 정보 교환과 관찰 가능한 결과를 기술. 내부 식별값·저장소는 결과나 액터로 표현하지 않음. |
| 4. 간결한 UC 그림 | 사용자/운영자/외부 제공자와 목표만 연결. 내부 협력은 도메인·시퀀스·클래스 절에서 설명. |
| 5. include의 의미 | 두 기능 모두 include 미사용. 실행 순서를 include로 나타내지 않음. |
| 6. 명세 분리·필수 항목 | 각 UC의 ID·이름·목적·주 액터·트리거·사전조건·기본 흐름·대안/예외·성공 보장 존재. 검색 ID를 표 머리글에서 명시 행으로 옮겨 확인을 쉽게 함. |
| 7. 목표와 구체 요구 분리 | 검색 3절 FR-C/W/A/B, 갱신 3절 FR-U에 기능 요구 기록. UI·정렬·데이터 계약은 OOD 절에 배치. |
| 8. OOA 선행·합의 | 사용자 결정(세 범위, 별도 갱신, 과거 기록 전체 열람)을 근거로 OOD 구체화. FR-A02 제한 방식·운영 수치·공급자는 제안이며 의존하는 분기까지 최종 확정이라고 표시하지 않음. 이 부분은 정책 확정 전까지 조건부 설계. |
| 9. OOD 추적 | 검색 9절, 갱신 10절에 클래스·저장 구조·읽기/쓰기 계약과 FR 연결. DTO·페이지·식별 참조 등 값 계약의 추적을 보완. 근거 없는 새 서버·테이블을 클래스마다 요구하지 않음. |
| 10. 시스템 경계 | 사용자/운영자/실제 원천 제공자만 UC 액터. 스케줄러·DB·서비스는 내부 참여자. 검색은 읽기 계약, 갱신은 수집·검증·쓰기 책임. |
| 11. 자체 검토 | UI 교체 후 목표 유지, 관찰 가능한 UC 흐름, UC 그림 내부 정보 배제, include 오용 없음, OOD 추적을 확인. 설명서의 그림도 원문 시퀀스와 대조해 수정. |
| 사용자 추가 규칙 | 도메인 다음 관계 중심 시퀀스, 그 다음 상세 클래스. 최초 시퀀스에 메서드 서명·SQL·커밋 구현을 넣지 않음. |

## 확정 사항과 남아 있는 제안

- **사용자 확정:** 한국·미국 주식/검증된 한글 별칭, 세 사용처의 검색 범위, 종목 검색과 갱신의 기능 분리, 관심종목 삭제·상폐 후에도 본인의 저장 브리핑 전체 검색·열람.
- **제안:** 신규 알림의 상폐·정지·확인 불가 상태 제한 방식(FR-A02), 60분 갱신·24시간 자료 이용 한도·재시도 수치, 실제 공급자와 운영 환경.
- **별도 기능의 미결정:** 기존 알림 자동 종료·평가 중단·복원. 이번 검색·갱신 설계가 이를 확정하지 않음.

새 합의 절차를 다시 시작하거나 이미 결정한 내용을 재질문하려는 구분이 아니다. 실제로 승인된 내용과 설계자가 제안한 내용을 혼동하지 않기 위한 기록이다.

## 문서 우선순위

최신 정책은 검색·갱신 두 기능 설계가 소유한다. `stock_search_recommendation_design.md`와 `stock_matching_review.html`은 초기 공통 설계 참고본이고, `stock_search_usage_and_refresh_design.md`는 분리된 문서로 연결하는 안내다. HTML 설명서는 대응하는 설계서의 시각 자료이며 독립 정책을 추가하지 않는다.

이번 검토는 로컬 문서 기준이다. 원격 PR이나 제품 코드가 이 변경과 같다고 보장하는 검토는 아니다.


## 2026-10-19 운영 정책 위임 반영
이전의 제안 상태는 갱신 설계의 최신 확정 절로 대체한다. 사용자 위임에 따라 주기·신선도·지원 범위·기존 알림 보류/재개·감사 보존을 정했으며 FR-U06~08/FR-A03과 도메인→관계 시퀀스→클래스로 추적한다. 실계정 키 부재는 합의 문제가 아니라 실행 환경의 검증 제한이다.
