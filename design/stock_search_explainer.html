2026-10-12 구현 반영

검색은 DB의 게시된 목록을 읽고 등록·알림 저장 직전에 상태를 다시 확인합니다. 한국 KRX 1시간, 미국 Alpha Vantage 6시간 갱신을 적용합니다. 원천일 7일 또는 정상 수집 48시간 초과는 자료 지연으로 판정합니다. 한국 목록 누락은 상폐 확정이 아니라 상태 미확인으로 표시합니다. 과거 브리핑은 그대로 찾을 수 있습니다.

기존 구독은 자동 연결하지 않습니다. 사용자가 같은 종목임을 확인하면 기존 구독과 알림 조건을 유지하며 연결합니다. 공급자 키 설정과 실제 계정 검증 전에는 자동 갱신을 켜지 않습니다.

내가 그 종목을 관찰하는 관계입니다. 삭제 후 다시 등록하면 새 관계가 됩니다.

저장 브리핑

과거 시점의 문서입니다. 한 문서에 여러 종목이 들어갈 수 있습니다.

종목이 상장폐지되어도 이미 작성된 브리핑까지 없어지는 것은 아닙니다.

2026-10-05에 확인한 코드 기준으로, main의 공통 종목 분석 이력과 PR #36의 개인 저장 브리핑은 다릅니다. 세 번째 흐름은 PR #36의 저장 브리핑을 기준으로 합니다. 아래 신규 검색 클래스는 구현 전 설계입니다.

1. 관심종목 등록 — 전체에서 찾기

“삼성이라고 입력하면 전체 지원 종목에서 후보를 찾습니다. 검색 담당은 후보를 보여줄 뿐이고, 내가 하나를 확인하면 등록 담당이 현재 등록 가능한 종목인지 다시 확인하고 내 관심종목에 넣습니다.”
등장 클래스쉽게 설명할 책임
CatalogScope전체 지원 종목 중 등록 가능한 범위를 정합니다.
SecuritySelectionService이름·코드·별칭으로 맞추고 원하는 순서로 정렬합니다.
WatchlistRegistrationService선택한 종목을 다시 확인하고 본인의 구독을 등록합니다.
WatchlistRepository관심종목 관계를 저장합니다.

사용자 결과: “삼성전자가 내 관심종목에 등록되었습니다.”

2. 알림 설정 — 내 관심종목 안에서 찾기

“알림 대상을 고를 때는 전체 시장이 아니라 내가 등록한 종목만 찾습니다. 후보를 고른 뒤 관심종목을 삭제했을 수도 있으니, 저장할 때 같은 구독이 유지되는지 한 번 더 확인합니다.”
등장 클래스쉽게 설명할 책임
WatchlistScope본인의 현재 관심종목에서 후보를 가져오고, 기준정보 읽기 계약으로 종목 정보를 확인합니다.
SecuritySelectionService같은 검색·정렬 방법을 사용합니다.
AlertConditionService본인의 같은 활성 구독인지 확인하고 알림 조건을 검증합니다. 종목 상태에 따른 신규 저장 제한은 설계 제안입니다.
AlertConditionRepository확인한 구독에 조건을 저장합니다.

사용자 결과: “내 관심종목의 알림 조건이 저장되었습니다.” 조건 저장이 즉시 메시지 발송을 뜻하지는 않습니다.

이 그림의 상태 검증은 제안: 상폐·정지·확인 불가를 이유로 새 조건 저장을 제한하는 구체 정책은 미확정입니다. 본인의 같은 구독인지 확인하는 책임과 구분해서 설명하세요.

3. 저장 브리핑 — 내 기록에서 찾기

“애플을 검색하면 내 저장 브리핑에 실제 대상으로 들어 있던 애플을 찾습니다. 확인하면 애플이 들어간 과거 문서를 보여줍니다. 애플과 마이크로소프트가 함께 들어간 문서는 어느 종목으로 찾아도 나와야 합니다.”
등장 클래스쉽게 설명할 책임
BriefingScope본인의 저장 문서에서 대상 종목을 모읍니다.
SecuritySelectionService그 범위 안에서 같은 매칭·정렬을 수행합니다.
BriefingSearchService선택한 종목과 기간으로 기존 목록·본문을 읽습니다.
BriefingHistory본인 소유 기록인지 확인해 반환합니다.

사용자 결과: “이 종목을 포함한 과거 브리핑 목록과 저장된 본문.” 새 분석 비용이나 카카오 전송이 발생하는 흐름이 아닙니다.

사용자 확정: 관심종목에서 삭제하거나 상폐된 종목도 본인 과거 기록 전체를 검색·열람합니다. 현재 상장종목만 거르면 과거 기록이 사라진 것처럼 보이므로 조회 기준을 나눕니다.

클래스 그림은 이 순서로 설명하세요

  1. SecuritySelectionService: 공통 검색 담당입니다.
  2. CandidateScope: 어디까지 검색해도 되는지 알려주는 약속입니다.
  3. 세 Scope: 전체 종목·내 관심종목·내 저장 기록이라는 서로 다른 범위를 같은 형태로 제공합니다.
  4. SearchSelection: 사용자가 확인한 대상 정보를 전달합니다. 등록 완료나 권한을 보증하는 증명서는 아닙니다.
  5. 세 후속 서비스: 실행 직전에 자신의 권한·상태를 확인하고 각각 등록·조건 저장·기존 문서 조회를 맡습니다.
“공통으로 묶는 것은 검색 방법이고, 각 기능이 가진 범위와 저장 규칙은 그대로 둡니다.”

그림 읽는 순서: 각 사용처의 목표를 먼저 설명하고, 시퀀스에서 누가 누구와 협력하는지 짚은 다음, 클래스에서 그 책임의 이름과 메서드를 설명하세요. 처음 시퀀스에서는 SQL·커밋 같은 구현 세부를 설명하지 않습니다.

점선 화살표는 다른 책임을 사용한다는 뜻이고, 빈 삼각형은 같은 인터페이스를 구현한다는 뜻입니다. 클래스 하나마다 별도 서버를 만드는 설계가 아닙니다.

정렬 예: ‘삼성’으로 찾은 뒤 이름 오름차순을 선택해도 선택한 종목은 바뀌지 않습니다. 먼저 본인의 허용 범위를 정하고, 그 안에서 매칭·정렬한 뒤 페이지를 자릅니다.

기준정보 갱신은 별도 기능입니다

“검색은 게시된 종목 정보와 자료 상태를 읽습니다. 원천 수집과 정기 DB 갱신은 별도 기능이 맡습니다.”

검색은 SecurityCatalogReader로 종목 정보·게시 버전·기준 시점·자료 상태를 읽습니다. 갱신을 직접 실행하거나 완료될 때까지 기다리지 않습니다. 직전 유효본이 있으면 사용하고, 없으면 정보 확인 불가를 안내합니다. 상폐되어도 본인 과거 브리핑은 검색합니다.

갱신 기능 쉬운 설명서 · 갱신 기능 설계서

왜 브리핑용 종목 연결 기록이 필요한가?

브리핑 한 개에 AAPL과 MSFT가 들어 있으면, “이 브리핑에 이 종목이 들어 있다”는 연결 기록을 두 개 둡니다. 종목으로 검색할 때 그 연결을 따라 원래 문서를 찾습니다.

“과거 원문을 그대로 두고, 그 문서에 포함된 종목과의 연결을 기록합니다. 오래된 티커가 어느 회사였는지 확실하지 않으면 추측해서 연결하지 않습니다.”

과거 원문과 대상 symbol은 그대로 보존합니다. 이관 중인 기록은 준비 상태를 표시하거나 기존 목록으로 읽을 수 있게 합니다. 다른 사용자의 연결 기록은 후보나 건수에도 노출하지 않습니다.

설명 후 나올 만한 질문

검색 기능을 세 개 따로 만드는 건가요?

공통 매칭·정렬은 하나입니다. 검색 가능한 범위를 세 구현으로 나누고, 결과를 받은 뒤의 등록·저장·열람은 각 기능이 맡습니다.

검색에서 확인했는데 왜 저장할 때 다시 확인하나요?

검색과 저장 사이에 관심종목을 삭제하거나 종목 상태가 바뀔 수 있습니다. 같은 구독과 현재 상태를 확인해야 잘못된 연결을 막을 수 있습니다.

상폐되면 DB에서 삭제하면 안 되나요?

삭제하면 과거 문서와 종목의 관계를 잃습니다. 상태와 이력을 남기고 신규 작업 가능 여부를 구분합니다.

현재 자료에 없던 옛 종목은 못 찾나요?

과거 브리핑 검색은 저장 당시 대상에서 시작합니다. 현재 카탈로그에 없더라도 본인의 기록은 남습니다. 정확한 종목 동일성을 모르면 당시 코드와 시점을 표시합니다.

새로 정해야 할 것은 무엇인가요?

삭제·상폐 종목의 본인 과거 기록 열람은 확정됐습니다. 운영 정책도 확정했습니다. 실제 계정 키를 설정한 뒤 응답 범위와 발표 지연·공유 한도를 검증해야 합니다.

기존 관심종목은 삭제하지 않고 연결합니다

2026-10-19 사용자 결정 반영 · 상세 설계 FR-L01~03

“전에 등록한 관심종목을 지우고 다시 만드는 게 아닙니다. 사용자가 이름과 코드를 보고 같은 종목이라고 확인하면, 그 관심종목에 현재 종목정보를 연결합니다. 기존 알림 조건과 과거 브리핑은 그대로 남습니다.”
  1. 웹에서는 미연결 종목의 ‘종목 정보 연결’을 누릅니다. 데스크톱에서는 아래 검색에서 같은 종목을 선택합니다.
  2. 이름·코드·시장·자료 기준을 확인하고 연결을 확정합니다. 취소하면 바뀌지 않습니다.
  3. 종목 선택 서비스는 현재 정보와 본인의 기존 관심종목이 유효한지 다시 확인합니다.
  4. 같은 구독에 연결 결과만 기록합니다. 삭제 후 다시 등록된 다른 구독에는 붙이지 않습니다.

보존되는 것: 기존 관심종목의 시작 시점, 알림 조건과 켜짐·꺼짐 상태, 과거 브리핑 원본과 검색 기록입니다.

거절되는 경우: 상폐·정보 만료, 다른 코드, 이미 다른 종목에 연결된 구독, 관심종목 등록 이후 상장된 후보입니다. 같은 코드가 다른 회사에 재사용됐을 가능성을 사용자 확인만으로 덮어쓰지 않습니다.

클래스 협력은 SecuritySelectionService → SecurityCatalogReader → WatchlistSubscription 순서로 설명하면 됩니다. 상세 시퀀스와 클래스 다이어그램은 검색 설계서의 ‘기존 관심종목 연결 보완’에 있습니다.
