# 카카오 알림 수신 확인

상태: 사용자 요청에 따라 구현. 실제 카카오 수신은 별도 확인 필요.

## 사용자 목표와 시스템 경계

시스템은 기존 웹과 PC 서버를 포함한다. 주 액터는 사용자이며 카카오는 외부 메시지 서비스다. 기존 알림 연결과 알림 전달을 재사용하며 종목 분석의 소유·공유 범위는 바꾸지 않는다.

### UC-NT-001 알림 수신 가능 여부를 확인한다

- 목적: 사용자가 연결한 카카오톡으로 알림을 받을 수 있는지 확인한다.
- 주 액터: 사용자
- 트리거: 사용자가 테스트 알림 발송을 요청한다.
- 사전조건: 로그인과 베타 이용 권한이 있고 카카오 알림이 연결되어 있다.
- 기본 흐름: 사용자가 수신 확인을 요청한다. 시스템은 해당 사용자의 연결로 테스트임을 명시한 메시지를 발송한다. 시스템은 발송 요청의 성공을 알리고 사용자는 카카오톡에서 실제 수신을 확인한다.
- 대안·예외: 연결이 없으면 연결을 안내한다. 세션 만료 시 재로그인을 안내한다. 전송 실패 또는 결과 불명 시 성공을 표시하지 않고 상태와 수신함 확인을 안내한다.
- 성공 보장: 카카오가 발송 성공을 응답한 경우에만 성공을 표시한다. 실제 기기의 알림 표시·읽음을 보장하지 않는다.

## 기능 요구사항

- FR-NT-001: 현재 사용자 자신의 활성 연결로 고정된 테스트 메시지 한 건을 보낸다. 수신자와 메시지를 외부 입력으로 받지 않는다.
- FR-NT-002: 기존 인증·베타 권한·쿠키 요청 출처 검사를 적용한다.
- FR-NT-003: 진행 중 중복 클릭을 막고 자동 재시도·오프라인 대기열을 사용하지 않는다. 연결된 경우에만 버튼을 표시한다.
- FR-NT-004: 분석·조건 평가·스케줄러·과거 알림 재발송을 실행하지 않는다. AI 호출은 발생하지 않는다.
- FR-NT-005: 성공은 카카오 발송 접수로 표현한다. 통신 실패 시 이미 전달되었을 가능성을 안내하며 인증 정보나 외부 응답 원문을 노출하지 않는다.
- FR-NT-006: 화면과 서버 모두 독립 컴포넌트로 구성한다.
- FR-NT-007: 메시지의 자세히 보기는 PC·모바일 모두 현재 웹 서비스의 메인 화면으로 연결한다. 특정 분석 상세 화면을 보장하지 않는다.

## 도메인과 협력 관계

도메인은 기존 사용자 계정 → 알림 연결 → 외부 채널로의 알림 전달 관계를 따른다. 테스트는 시장 신호나 사용자 알림 조건의 충족을 의미하지 않는다. 분석에 종속된 기존 전달 이력에 가짜 분석을 만들지 않고 별도 저장 구조도 추가하지 않는다.

UC-NT-001의 협력: 사용자 → 테스트 발송 컴포넌트 → 인증 경계 → 테스트 발송 서비스 → 본인 연결 조회 → 기존 전송기 → 카카오. 결과는 역순으로 사용자에게 전달한다.

## 상세 책임과 인터페이스

- `TestNotificationButton`: FR-NT-003·005·006. 재사용 가능한 React 컴포넌트로 발송·즉시 중복 방지·결과 표시를 자체 관리한다. API와 세션 만료 콜백을 주입받으며 카카오 연결 관리 컴포넌트를 참조하지 않는다.
- `NotificationConnectionPanel`의 `children`: FR-NT-003·006. 기존 연결 영역 안에 자식 컴포넌트를 합성한다. 연결 여부에 따라 자식 표시만 관리하며 테스트 발송 로직이나 구체적인 자식 종류를 알지 않는다. 상위 화면에서 둘을 조합한다.
- `NotificationTestService`: FR-NT-001·004·006. 사용자 계정으로 연결을 조회하고 기존 `NotificationSender`에 고정 메시지를 전달한다.
- 별도 API 모듈의 `POST /notification-connections/kakao/test`: FR-NT-002·005. 성공 204, 연결 없음 409, 전송 실패 502, 설정 미비 503. 발송 대상은 인증 계정에서 결정한다.
- 기존 카카오 전송기: 토큰 갱신과 메시지 전송을 재사용한다. 요청 내 진행 방지 외에 서버의 동시 요청 제한이나 영속 중복 제거는 추가하지 않는다.
- 메시지 링크(FR-NT-007): 공통 카카오 전송기가 `WEB_ORIGIN`의 마지막 슬래시를 제거하고 `/app`을 붙여 `web_url`·`mobile_web_url`에 동일하게 지정한다. 설정이 없으면 기존 로컬 기본 출처를 사용한다. 카카오 제품 링크 관리의 웹 도메인 등록이 필요하며 로그인 콜백 등록과 구분한다. 공통 전송기를 사용하는 일반 알림에도 적용되며, 이미 발송된 메시지는 변경되지 않는다.

## 검증

본인 연결 선택, 연결 없음·실패·권한·출처 차단, 전송 HTTP 대역, 화면 중복 클릭·성공·실패·세션 만료와 API 경계를 검사한다. 실제 발송은 사용자가 버튼으로 별도 확인한다.

카카오 응답은 대역으로 검증하며 실제 수신은 별도 확인한다. 연결 해제 시 자식 버튼을 숨기고, 발송 시에는 서버가 현재 계정의 활성 연결을 다시 확인한다.

재사용 예시:

```tsx
<NotificationConnectionPanel api={api} onSessionExpired={onSessionExpired}>
  <TestNotificationButton api={api} onSessionExpired={onSessionExpired} />
</NotificationConnectionPanel>
```

테스트 버튼에 필요한 API는 `sendTestNotification` 하나다. 다른 화면에서는 버튼만 독립적으로 배치할 수 있다. 자식 합성, 연결 해제 후 숨김, 독립 발송·중복 방지·실패 표시를 웹 테스트로 확인한다.

자체 검토: 사용자 목표는 UI 교체 후에도 성립하며 기본 흐름은 외부 상호작용으로 작성했다. 내부 요소는 상세 설계에만 기록하고 각 요소를 UC·FR에 연결했다. 유스케이스 다이어그램과 include 관계는 필요하지 않아 추가하지 않았다.
