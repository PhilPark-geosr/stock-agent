# 모의투자 가격 데이터 재사용 검토

- 확인일: 2026-10-26
- 이슈: [#44](https://github.com/PhilPark-geosr/stock-agent/issues/44)
- 조사 브랜치: `codex/paper-trading-design`
- 관련 문서: [Inception의 범위·핵심 위험](paper_trading_requirements.md), [Elaboration 준비 자료의 상세 요구사항·예외](paper_trading_elaboration_notes.md). 관련 ID: FR-PT-010·014·015·018·021~025 및 초안 FR-PT-002·004·005·006·008
- 상태: 코드 조사 및 제한된 외부 조회 결과. 공급자·주문 방식·체결 정책 채택 전.

## 결론

기존 코드에는 국내 종목 식별·관심 종목·분석 조회와 일봉 수집의 재사용 기반이 있다. 그러나 기존 분석의 저장 가격을 그대로 매수·매도 시점의 현재가로 사용할 수는 없다. 현재 구현만으로 TradingView와 같은 실시간 호가 기반 모의 체결이 가능하다고 판단할 근거는 없다.

모의투자에는 AI 분석과 독립된 가격 조회, 가격의 기준 시각·수집 시각·지연·오래됨 구분, 보유 종목의 가격 갱신 정책이 필요하다. 아래 항목은 조사에서 도출한 설계 제안이며 신규 요구사항으로 합의한 것은 아니다. 구현은 변경하지 않았다.

## 1. 코드에서 확인한 사실

| 항목 | 현재 상태 | 근거 |
| --- | --- | --- |
| 가격 공급 | `yfinance`로 Yahoo Finance 시계열 조회 | `app/integrations/yfinance_market_data_provider.py`, `pyproject.toml` |
| 수집 단위 | 기본 최근 3개월 일봉, 최근 최대 60개 반환. 배당·분할 자동 조정 비활성화 | 같은 파일의 생성자와 `fetch` |
| 분석 가격 | 마지막 일봉의 `Close`를 `latest_close`로 사용 | 같은 파일의 `_build_indicators` |
| 시각 | 마지막 봉의 인덱스를 `data_time`으로 전달. 가격이 실제 관측된 시각과 조회 완료 시각을 별도 관리하지 않음 | 같은 파일의 `fetch`, `app/schemas/schemas.py` |
| 분석 조회 | 저장된 최신 분석이 있으면 반환하고 시세를 새로 조회하지 않음 | `app/services/services.py`의 `get_latest_analysis` |
| 새 분석 | 가격 조회 후 AI 분석을 실행하여 저장 | 같은 파일의 `analyze_and_store` |
| 자동 실행 | 기본 60분 간격으로 분석 실행. 환경 설정으로 바뀔 수 있음 | `app/core/scheduler_config.py`, `app/core/scheduler_runtime.py` |
| 시간 제한 | 기본 한국 시간 08시 이상 16시 미만의 시간대만 판별. 이 경로는 주말·휴장일·시장별 세션을 판별하지 않음 | `app/core/trading_window.py`, `app/services/scheduler.py` |
| 수집 대상 | 활성 관심 종목의 중복 제거 목록 | `app/services/services.py`의 `run_scheduled_batch` |
| 웹 표시 | 분석 시점 종가와 데이터 시각 표시. 독립적인 현재가·호가 조회 기능은 확인되지 않음 | `web/src/components/AnalysisPanels.tsx`, `web/src/api.ts`, `app/api/routes.py` |
| 브리핑 자료 | 별도 경로도 일봉 사용. 수집 시각과 거래일 마감 기준 자료 시각을 분리하는 기존 사례가 있음 | `app/integrations/briefing_sources.py` |
| 국내 종목 목록 | KRX 종목 기본정보로 KOSPI·KOSDAQ 보통주·우선주와 `.KS`·`.KQ` 기호를 구성. 이는 실시간 시세 수집이 아님 | `app/integrations/catalog_sources.py` |

### 해석 시 주의

- 일봉은 봉의 단위이며, 60분은 분석 작업의 실행 간격이다. 60분봉이나 60분마다 확정되는 현재가를 뜻하지 않는다.
- 일봉의 마지막 `Close`는 장중 미완성 봉의 값일 가능성도 있으므로 항상 확정 종가라고 단정하지 않는다.
- 일봉 인덱스가 당일 00:00이라고 해도 그 시각에 실제 거래 가격을 관측했다는 뜻은 아니다. 기존 `data_time`만으로 시세 최신성을 판단하기 어렵다.
- 같은 수집기의 `interval`만 분봉으로 바꾸면 최근 3개월 요청 범위, 반환 개수와 이동평균·변동성 계산의 의미도 달라진다. 기존 공통 분석에 그대로 적용하는 것은 적절하지 않다.
- 기존 08~16시 시간대 도우미를 모의투자의 실제 거래 가능 시간 규칙으로 채택하지 않는다.

## 2. 외부 조회 확인

설치된 `yfinance 0.2.66`을 사용하여 AI 호출·주문·DB 변경 없이 공개 가격 데이터만 조회했다. 라이브러리 캐시는 임시 폴더로 지정했다.

- 조회 시작: 2026-10-26 08:20:39 KST
- 일봉 요청: `period=5d`, `interval=1d`
- 분봉 요청: `period=1d`, `interval=1m`
- 공통: `auto_adjust=False`, `actions=False`, 요청 제한 시간 10초

| 종목 | 일봉 응답 | 마지막 일봉 인덱스 | 1분봉 응답 | 마지막 1분봉 인덱스 |
| --- | --- | --- | --- | --- |
| 삼성전자 `005930.KS` | 5행 | 2026-10-23 00:00 KST | 360행 | 2026-10-23 14:59 KST |
| SK하이닉스 `000660.KS` | 5행 | 2026-10-23 00:00 KST | 360행 | 2026-10-23 14:59 KST |

확인한 것은 두 종목에서 일봉·분봉 응답을 받았다는 사실이다. 마지막 1분봉 이후 구간의 완전성이나 그 원인은 검증하지 않았다. 장중 반복 조회, 실제 시세 대조, Bid/Ask, 거래 정지·휴장·오류 사례와 공급 지연은 검증하지 않았다. 이 결과로 실시간성·정확성·전 종목 지원을 보장하지 않는다.

## 3. 공식 자료 확인

- 설치 버전의 [yfinance 공식 소스](https://raw.githubusercontent.com/ranaroussi/yfinance/0.2.66/yfinance/scrapers/history.py)는 분봉 등 여러 조회 간격을 지원하며 장중 과거 데이터 범위에 제한이 있음을 설명한다. 분봉 지원은 무지연 시세 보장을 의미하지 않는다.
- [yfinance 공식 안내](https://ranaroussi.github.io/yfinance/)는 Yahoo가 승인한 도구가 아니며 연구·교육 목적이라고 설명하고, 실제 데이터 사용 권한은 Yahoo 이용 조건을 확인하도록 안내한다. 개인 사용과 서비스 배포·재배포 가능 여부를 같은 것으로 보지 않는다. 라이브러리 사용 비용과 시세 이용 권한도 구분한다.
- Yahoo의 거래소별 지연 안내 원문은 이번 조회에서 HTTP 429로 읽지 못했다. 따라서 특정 지연 시간을 검증된 수치로 기록하지 않는다.
- [한국투자증권 공식 샘플](https://github.com/koreainvestment/open-trading-api)은 국내 현재가 REST 조회와 실시간 호가 구독 예제를 제공한다. 공식 시세 공급을 검토할 수 있는 후보가 있다는 사실까지 확인했으며 인증을 이용한 실조회는 하지 않았다. [제휴 안내](https://apiportal.koreainvestment.com/provider)는 제삼자 서비스의 시세 이용에 별도 계약 검토가 필요한 경우를 설명하므로 개인 계정 연결 가능성과 서비스 배포 가능성을 분리해서 확인한다.

## 4. 재사용 범위와 추가 검토

| 구분 | 판단 |
| --- | --- |
| 로그인·관심 종목·공통 분석 조회 | 기존 기능을 연결할 기반이 있음. Android 인증·오프라인 지원 완료를 의미하지 않음 |
| 종목 식별·외부 기호 변환 | 기존 카탈로그를 활용할 후보. 카탈로그 등재만으로 시세 가용성을 보장하지 않음 |
| 일봉·지표 수집 | 분석과 참고 가격에 활용할 기반. 저장 분석의 마지막 가격으로 현재 매매를 체결하는 근거는 부족 |
| `yfinance` 분봉 | 개인 검증용 후보. 장중 지연·누락·이용 범위와 장애 동작을 더 확인해야 함 |
| 호가 기반 체결 | 현재 코드에 해당 경로가 없어 별도 시세 공급과 체결 정책 검토 필요 |
| 관심 종목에서 삭제한 보유분 평가 | FR-PT-015에 따라 계속 관리해야 하므로 활성 관심 종목만 수집하는 기존 배치로는 충분하지 않음 |
| 연습 종료 평가 | FR-PT-021에 따라 가격 기준 시각을 확인해 종료 결과를 보존해야 함. 가격 확보 실패 시 처리는 미정 |
| 매매·잔고·손익·거래 이력 | 새 기능이 필요. 이번 조사에서 클래스·DB·API를 확정하지 않음 |

## 5. 다음 논의를 위한 후보 — 미채택

1. **기존 공급자의 분봉을 활용한 간소화 모의투자**: 가격 기준 시각과 지연·누락을 표시하고, 단일 기준 가격으로 가상 체결하는 규칙을 별도 합의한다. 호가·실제 유동성을 재현했다고 표현하지 않는다. 오래된 봉을 다시 조회했다고 현재 가격으로 취급하지 않는다.
2. **국내 공식 시세 API 기반 모의투자**: 현재가·호가 확보와 사용 조건을 검토한 뒤 공급자를 정한다. 인증·계좌 요건, 호출 한도, 개인 이용과 배포 시 권한을 확인해야 한다. API 존재만으로 우리 서비스에 무료로 배포 가능하다고 단정하지 않는다.

판단 연습의 가격 기준을 명확히 하기 위해 두 번째 후보를 추가 조사하는 것을 추천한다. 공급자 채택이나 실시간성 요구를 확정한 것은 아니다. 첫 번째 후보도 장중 검증 전에는 구현안으로 확정하지 않는다.

### 조사 후 요구사항 논의 반영 (2026-10-26)

사용자는 증권사 계정·시세 API 연결 절차를 후속 작업으로 미루고, AI 분석과 독립적인 가격 조회와 관심 종목 등록 여부에 무관한 보유 종목 가격 조회를 요구했다. 이는 요구사항 FR-PT-022·023에 기록했다. 이어 화면 조회 중 가격·평가손익 자동 갱신과 매매 시 가격 재확인을 선택했으며 FR-PT-024·025에 기록했다. 화면을 닫은 동안의 상시 수집은 초기 필수 범위에 포함하지 않는다. 매매 가격 조회 실패·오래된 가격이면 매매를 차단하고 재시도를 안내하는 정책은 FR-PT-025의 예외 조건으로 합의했다. 갱신 주기·허용 지연과 화면 갱신·종료 평가 실패 처리는 미정이며, 위 공급자 후보는 채택 결정이 아니다.
