## 분리 기준과 합의 보존

Inception에는 목적·액터·시스템 경계·초기 범위·핵심 사용자 목표와 위험을 남긴다. 아래에는 금액 설정, 연습의 생명주기, 관심 종목 삭제 후 처리, 갱신 조건과 예외 등 Elaboration에서 구체화할 상세 동작을 분리했다. 이는 문서의 상세 수준을 나누는 것으로, 해당 정책이 Inception에서 논의될 수 없다는 뜻은 아니다.

이미 합의한 상세 정책은 재승인받지 않고 후속 분석에 적용한다. 초안과 미결정 항목은 합의로 승격하지 않는다. 상위 범위의 FR-PT-011·014·019·022는 Inception 문서에 유지한다. 미국 주식 확장은 Inception의 후속 목표다. 기존 FR-PT-010은 2026-10-26 검토에 따라 Inception의 목적·초기 범위로 재분류했으며 해당 ID는 변경 이력용으로 보존한다.

현재 시장 방식은 미래 가격을 앞당겨 보여주는 연습이 아니다. 보유 중의 가격 변화는 실제 시간 경과에 따라 관찰한다. 이 합의가 거래소 실시간 시세 공급, 특정 갱신 주기, 특정 주문·체결 방식을 보장하는 것은 아니다. 과거 재생 방식은 초기 연습 방식으로 선택하지 않았다.

투자 범위 합의는 현금·보유 수량 한도를 정한 것이다. 추가 매수와 부분 매도를 지원하며, 수수료를 포함한 매수 가능 금액과 미체결 주문에 사용할 자금·수량의 확보 방식은 후속 정책에서 정한다. 사용자가 요청 수량을 나누어 매도하는 부분 매도와 하나의 주문이 일부만 체결되는 부분 체결은 구분하며, 부분 체결 지원 여부는 미정이다.

미국 주식 확장 일정은 미정이다. 국내 대상 종목·상품의 세부 범위와 미국 확장 시 시세 제공, 통화·환율, 거래 시간, 소수점 거래 및 기존 계좌·이력 처리 정책은 별도 검토한다. 초기 국내 주식 지원이 미국 주식 지원까지 완료했다는 의미는 아니다.

관심 종목 등록과 가상 보유는 구분한다. FR-PT-014의 관심 종목 제한은 매수 대상에 적용하며, 삭제된 기존 보유분의 조회·매도는 FR-PT-015에 따라 허용한다. 관심 종목 삭제로 가상 매도가 자동 실행되거나 보유분·거래 이력이 삭제되지 않는다. 다시 등록해도 기존 보유분과 거래 이력은 유지한다. FR-PT-023에 따라 진행 중인 연습의 보유분은 관심 종목에서 삭제해도 가격 조회 대상에서 제외하지 않는다. 화면 조회 중 자동 갱신과 매매 시 가격 재확인은 FR-PT-024·025에 따르며, 정확한 갱신 주기는 후속 정책에서 정한다.

가격 조회는 AI 분석 실행과 독립적으로 제공한다. 증권사 계정·시세 API 연결 절차의 구체화와 구현은 사용자의 요청에 따라 후속 작업으로 미룬다. 이번 결정으로 특정 공급자를 채택하거나 실시간 시세 확보가 완료된 것으로 보지 않는다.

### 가격 갱신 범위와 남은 정책

2026-10-26 사용자는 화면을 보는 동안의 갱신과 매매 시 가격 재확인을 선택했다. 매매 가격 조회 실패·오래된 가격에 대한 예외 처리도 합의했으며, 구체적인 주기·허용 지연은 미정이다.

- 가격·보유 현황 화면을 보는 동안 가격과 평가손익을 자동 갱신한다. 다시 화면을 열었을 때도 새 가격을 확인한다.
- 매매 처리 시 가격을 다시 조회하고 기준 시각·최신성을 확인한다. 실패·오래된 가격은 아래 FR-PT-025의 예외 조건을 적용한다. 재조회 가격이 화면 표시 가격과 달라졌을 때 사용자의 재확인을 받을지는 별도로 정한다.
- 화면을 닫은 동안의 상시 가격 수집과 시간별 자산 변화 이력은 초기 필수 범위에 포함하지 않는다. 미체결 주문·손절 등 자동 감시 지원은 이번 합의에 포함하지 않으며 별도로 논의한다.
- 정기 조회와 공급자의 변경 통지 수신은 가능한 기술 후보이며 아직 선택하지 않는다. 짧은 간격으로 요청하는 것만으로 공급 지연이 사라지거나 실시간성이 보장되지는 않는다.
- PC 중단·연결 실패·휴장·시세 누락 시 처리는 별도 정책이며, 종료된 연습 기록은 지속 갱신 대상에 넣지 않는다.

### FR-PT-025 예외 조건 — 매매에 사용할 가격을 확보할 수 없음

2026-10-26 사용자 합의. 별도 기능 요구사항 ID를 추가하지 않고 기존 가격 재확인 요구사항에 연결한다. 후속 매매 유스케이스 명세에서는 예외 흐름으로 기술한다.

- 발생 조건: 매매 시 가격 조회에 실패하거나, 조회된 가격이 허용 최신성 기준을 벗어난 경우.
- 시스템 응답: 해당 매매를 차단하고, 처리할 수 없는 이유와 재시도 안내를 사용자에게 제공한다.
- 결과 보장: 해당 요청으로 가상 체결을 생성하거나 현금·보유 수량을 변경하지 않는다.
- 미결정 세부 정책: 오래된 가격을 판단할 허용 지연과 기준 시각. 연습 종료 평가나 화면 갱신 실패의 처리는 이 매매 예외와 구분하여 정한다.

초기 가상 자금은 고정 1,000만원으로 정하지 않고 사용자가 지정한다. 허용 금액 범위·단위·기본 제안값은 미정이다. 연습 시작 후 초기 금액을 바꾸거나 자금을 추가 입금하지 않으며, 다른 초기 금액으로 시작할 때 이전 기록을 덮어쓰거나 삭제하지 않는다. 초기 금액 유지가 매매에 따른 현금 잔액이나 손익의 변화를 막는다는 의미는 아니다.

하나의 연습은 여러 종목을 함께 운용하는 단위이며 종목 하나를 뜻하지 않는다. 동시에 진행하는 연습은 사용자별 하나이고, 새 연습 시작 시 이전 연습은 종료된다. 종료 시 보유분은 자동 매도하지 않고 당시 상태로 보존하며, 평가손익을 실현손익으로 바꾸지 않는다. 이후 시장 가격이 바뀌어도 종료 기록의 평가 결과는 변하지 않는다. 종료 당시 평가에 사용할 가격의 기준 시각·최신성 조건과 가격 확보 실패 시 처리, 미체결 주문의 종료 처리, 상세 보존 범위는 후속 정책으로 정한다. 이전 보유분을 새 연습으로 이관하는 정책은 합의하지 않았다.

## 3. Elaboration에서 구체화할 정책

다음은 논의 항목이며 채택된 정책이 아니다. 중요한 정책은 한 번에 하나씩 논의한다.

1. 국내 대상 종목·상품의 세부 범위와 가격 데이터 확보 가능성, 비용·이용 조건, 허용 지연·자동 갱신 주기, 재조회 가격 변동 시 사용자 재확인 여부. 매매 가격 조회 실패·오래된 가격의 처리는 FR-PT-025 예외 조건으로 합의했으며, 증권사 API 연결 절차의 구체화·구현은 후속 작업으로 보류
2. 주문 방식과 체결·평가 가격 기준, 거래 가능 시간, 미체결·부분 체결 지원
3. 초기 자금의 허용 범위·단위·기본 제안값, 미체결 주문의 연습 종료 시 처리, 종료 평가 가격의 기준 시각·최신성 및 확보 실패 시 처리, 수수료·세금·배당·환율
4. PC 중단과 연결 단절 시 요청·미체결 주문 처리, 상태 확인과 중복 처리 방지
5. 모바일 잔고·이력 보관 범위, 마지막 갱신 시각과 오프라인 조회
6. 기록한 매매 이유의 조회·수정 범위, 기대한 변화·후속 회고와 결과 비교 기능, 이전 연습 기록의 보존 범위·기간과 조회 방식, 결과 공유 범위
7. 미국 주식 확장 일정과 통화·환율·거래 시간·시세·소수점 거래·계좌 및 이력 처리 정책

개인 PC·Android 이용과 기존 오프라인 분석 조회 정책은 유지한다. 다만 새 가상 매매 차단, 잔고 보관과 PC 중단 중 주문 처리에 대한 구체적인 적용은 추가 논의한다. 기존 종목 분석의 공통 결과 정의와 개인 실행 결과의 소유·공유 범위는 변경하지 않는다.

## 4. 검증과 후속 설계

2026-10-26 기존 가격 수집 코드와 두 국내 종목의 일봉·1분봉 응답을 확인했다. 결과는 [가격 데이터 재사용 검토](paper_trading_market_data_review.md)에 기록한다. 기존 일봉·저장 분석을 현재 매매 가격으로 그대로 사용할 수는 없으며, 장중 지연·정확성·호가와 이용 범위는 추가 검증이 필요하다. 이번 조사로 시세 공급자·체결 방식이 확정된 것은 아니다.

시세와 기존 기능의 재사용 가능성을 확인한 뒤 초기 정책과 OOA를 구체화한다. 유스케이스는 사용자 목표로 이름 짓고 외부에서 관찰 가능한 상호작용·예외·성공 보장을 작성한다. 명세와 다이어그램은 분리한다.

OOA 합의 전 클래스·저장 구조·API를 확정하지 않는다. 이후 도메인 모델 → 관계 중심 시퀀스 → 상세 클래스 순서로 작성하며 유스케이스·요구사항과 추적 관계를 표시한다.

## 5. 도메인 모델 검토에서 확인한 의미

합의된 관계를 반영한 그림은 [모의투자 도메인 모델](paper_trading_domain_model.md)에 정리한다. 평가 가격 정보의 표현은 검토 중으로 구분한다.

회고를 제외한 UC-PT-01~05를 대상으로 초기 개념을 검토한다. 용어 정의는 [CONTEXT.md](../CONTEXT.md)의 모의투자 항목을 따른다.

- 자산은 하나의 투자 연습의 현재 현금과 보유 주식을 묶는 개념이다.
- 거래는 이미 체결된 매수 또는 매도의 기록이다. 해당 거래의 종목·수량·체결 가격·체결 시각을 구분한다. ‘매수·매도’가 실행 기능이나 미체결 요청을 뜻하는 것은 아니다.
- 매수 거래의 결과는 현금 감소와 해당 종목의 보유 수량 증가로, 매도 거래의 결과는 보유 수량 감소와 현금 증가로 자산에 반영된다. 비용 반영과 손익 산정의 상세 규칙은 기존 미결정 정책을 따른다.
- 거래는 당시 발생한 사실, 자산은 그 결과인 현재 상태를 나타낸다. 거래와 자산 상태가 서로 일치해야 한다. 거래 기록으로부터 보유 상태를 계산할지 별도로 유지할지는 여기서 확정하지 않는다.
- 포트폴리오는 같은 투자 연습의 자산 구성과 평가 결과를 나타낸다. 자산과 포트폴리오가 각각 별도의 현금·보유 주식을 소유한다고 모델링하지 않는다. 이 개념은 UC-PT-05와 연결된다.
- 이 관계는 UC-PT-02·03, 현금·보유 수량 한도 FR-PT-011, 부분 매도·추가 매수 FR-PT-018과 연결된다. 현재 상태를 확인하는 목적은 UC-PT-05와 연결된다.

‘거래 결과를 자산에 반영한다’는 의미는 합의했지만, 거래 객체가 직접 자산을 갱신하는 메서드를 가져야 한다는 설계까지 확정한 것은 아니다. 매수·매도를 별도 구현 클래스로 나눌지, 어떤 객체가 갱신 책임을 맡을지는 후속 협력 설계에서 검토한다. 포트폴리오의 구현 형태와 평가 가격·시각의 표현은 추가 논의한다.
