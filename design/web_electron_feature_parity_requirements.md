# Electron 사용자 기능의 웹 이전 요구사항

기준: 현재 `desktop-demo/` 렌더러·preload·main과 FastAPI API 코드. 이 문서는 웹 구현과 테스트의 수용 기준이다. 기존 초대·베타 권한 설계는 유지한다.

## 공통 원칙

- 중앙 FastAPI가 공통 종목 분석을 저장한다. 분석 결과는 사용자별 조건이나 알림 연결에 따라 달라지지 않는다.
- 사용자 알림 조건의 평가는 공통 분석 저장 이후 배치 흐름에서 사용자별로 수행한다. 카카오 연결과 발송 결과는 로그인 및 공통 시장 신호와 별개이다.
- 개인 Gemini API 키, 실시간 시세, 조건 수정·켜기/끄기, 평가·발송 이력 화면, 화면에서의 강제 스케줄러 실행은 이 이전 범위가 아니다.
- 모든 일반 기능은 기존 로그인·베타 이용 권한과 본인 관심종목 구독 검사를 따른다. 웹의 기존 초대 등록·운영자 발급 기능을 유지한다.

## 기능별 사양과 수용 기준

### 관심종목

- Electron: 목록 조회·추가·삭제·선택, 현재 목록 안의 코드/이름 검색. 접미사 없는 코드는 `.KS`를 붙인다. 화면의 이름은 현재 코드에서 종목 코드와 같다.
- 웹: 동일한 관리·검색·코드 보완을 제공한다. 선택 시 저장된 최신 분석과 이력을 표시한다. 목록이 비거나 API가 실패해도 이전 종목 결과를 보여주지 않는다.

### 공통 분석과 이력

- Electron: 종목 선택 시 최신 분석과 최근 이력 20건을 읽는다. `GET /stocks/{symbol}/analysis/latest`는 저장 결과가 없으면 분석을 생성한다. 이력 선택 시 해당 상세를 독립 분석 화면에 표시한다. 수동 실행은 `POST /stocks/{symbol}/analysis`로 공통 결과를 새로 저장한다.
- 웹: 종목 선택 시 저장 이력 첫 항목의 상세를 최신 결과로 표시한다. 이력이 없으면 빈 상태와 수동 분석 실행 버튼을 표시하며, 조회만으로 새 분석을 생성하지 않는다. 수동 실행 후 결과와 이력을 갱신한다. 중복 클릭을 막되 별도 서버 사용량 제한은 이번에 추가하지 않는다. 기존 20건 단위 이력 추가 로딩과 과거 상세 조회를 유지한다.
- 분석 화면에는 종목, 분석 시각, 판단, 요약, 주요 근거, 위험 요인, 데이터 시각, 거래량 20일 평균 대비 비율, 20일 저가·고가, 공통 시장 신호를 표시한다. `support_levels.latest_close`와 `change_percent`는 실시간 값이 아니라 선택한 분석의 저장 시점 값이므로 **분석 시점 종가·등락률**로 표기한다. 누락값은 임의의 0으로 바꾸지 않는다.
- 공통 분석의 `should_alert`, `triggered_alerts`, `alert_reason`은 시스템 시장 신호이다. 이것을 특정 사용자의 조건 충족이나 카카오 발송 완료로 표시하지 않는다. 수동 분석과 최신 조회의 최초 생성은 현재 서버에서 알림 발송을 실행하지 않는다.

### 사용자 알림 조건

- Electron: 종목 코드와 자유 문장 규칙을 등록하고, 검증 요약과 함께 목록을 조회·삭제한다. 수정이나 활성 상태 전환 화면은 없다.
- 웹: 선택 종목을 기본값으로 하되 코드와 문장을 편집해 등록한다. 서버의 422 검증 거절은 `validation_summary`와 `rewrite_guidance`를 표시한다. 등록·삭제 후 목록을 갱신한다. 조건은 사용자 계정과 활성 관심종목 구독 범위에 속한다. 기존 배치의 사용자별 평가·카카오 전달 흐름을 유지한다.

### 카카오 알림 연결

- Electron: 로그인과 독립적으로 연결 상태를 읽고, 카카오 승인 창을 열어 연결한 뒤 상태를 재조회하며 연결을 해제한다.
- 웹: 상태·연결·해제를 제공한다. 모바일에서는 같은 탭으로 카카오에 이동하고 승인 후 웹 앱으로 돌아온다. 웹에서 시작한 요청만 고정된 `WEB_ORIGIN`으로 복귀하며 Electron의 기존 콜백 완료 화면은 유지한다. 복귀 URL의 표시값을 신뢰하지 않고 서버 상태를 다시 조회한다. 연결 실패·설정 불가·세션 만료를 구분해 안내한다.

## 검증 순서

기능별 실패 테스트를 먼저 작성한 다음 최소 구현과 리팩터링을 수행한다. API/React 단위 테스트는 종목 전환 중 늦은 응답, 분석 빈 상태·최신/과거 전환·수동 실행, 누락 지표, 조건 검증 거절, 알림 연결 왕복을 다룬다. FastAPI 테스트는 웹 콜백 복귀와 변조·만료 state, Electron 호환성을 검증한다. Playwright에서 모바일 크기의 주요 흐름을 검증하고 외부 카카오·유료 AI 호출은 대역으로 처리한다.

## 구현 및 검증 기록

- 웹은 `WatchlistPanel`, `AnalysisPanel`, `AnalysisHistoryPanel`, `AlertConditionsPanel`, `NotificationConnectionPanel`을 독립 컴포넌트로 구성하고 `/app`에서 조합한다. 공통 API 클라이언트에 수동 분석·조건·알림 연결 계약을 추가했다.
- 서버는 알림 연결 요청의 암호화된 state에 웹/ Electron 시작 경로를 기록한다. 웹 요청은 고정된 `WEB_ORIGIN/app`으로 돌아오고 기존 Electron 요청은 완료 HTML을 받는다. 웹 화면은 복귀 표시값을 지운 뒤 저장된 연결 상태를 다시 읽는다.
- 테스트는 저장 결과가 없는 종목의 빈 상태, 최신·과거 전환, 수동 분석 완료 뒤 이력 갱신 실패, 조건 거절 안내, 알림 연결·해제, 모바일 흐름을 확인한다. 모바일 통합의 카카오 동의·조건 검증은 대역으로 확인했으며 실제 카카오 계정과 외부 AI를 호출하지 않았다.
- 검증 결과: Python 136개, Electron 15개, 웹 단위 36개, Playwright 6개 통과. 웹 타입 검사·프로덕션 빌드와 Electron 구문 검사 통과.
