## 현재 구현과 비용 검토

현재 중앙 서버는 여러 클라이언트의 API 요청을 처리하고, 정기 분석에서는 활성 구독 종목의 중복을 제거해 종목별 공통 분석을 생성한다. 화면 조회는 요청·응답 방식이며, 조건부 알림 발송과 구분한다. 공통 종목 분석 비용은 사용자 수에 그대로 비례하지 않으며, 분석 대상 종목 수와 빈도에 영향을 받는다. 사용자별 알림 평가와 투자 브리핑은 별도의 사용자별 작업이다.

React 원본은 `web/src`, 빌드 결과는 `web/dist`에 있다. FastAPI는 `/login`, `/app` 등에서 빌드된 화면과 `/assets` 정적 파일을 제공하고, 브라우저가 React를 실행한다. 따라서 Python 서버만 실행해도 이미 빌드된 웹 화면을 제공할 수 있으며 Vite 개발 서버를 함께 실행한 것은 아니다. 화면 소스 변경은 다시 빌드해야 반영된다.

근거: `app/services/services.py`, `app/api/web_pages.py`, `app/main.py`, `web/src/api.ts`, `web/src/styles.css`, `README.md`.

## 배경과 배포 방향

운영자가 유료 AI API 비용을 부담하기 어려운 초기 단계에는 사용자 개인 PC에서 분석 서버를 실행하고 모바일 클라이언트로 이용하는 방향을 검토한다. 데스크톱에서만 이용하는 버전으로 대체하지 않으며, 초기부터 집 밖의 모바일 데이터 및 다른 Wi-Fi에서도 결과를 확인할 수 있어야 한다.

이후 비용을 확보하면 중앙 분석 서버로 이전하는 것을 목표로 한다. 이전 시 모바일의 설정·요청·조회 기능을 유지하는 방향으로 검토하되, 실제 이전 방법과 데이터 이동 정책은 아직 확정하지 않았다. 현재 구현을 이미 변경했다는 뜻은 아니다.

개인 PC 실행은 초기 비용 제약 아래 분석의 유용성과 모바일 이용 경험을 검증하기 위한 선택이다. 비용 지원·후원 등은 아직 확보되지 않았으며, 향후 중앙 운영의 재원 확보를 전제한 일정이나 규모는 정하지 않았다. PC를 계속 켜두어야 하고 초기 설치·연결 부담이 사용자에게 생기는 점을 받아들인다.

## 검토한 대안과 선택 이유

| 대안 | 논의 결과 |
| --- | --- |
| 중앙 서버 + 운영자 API 키 | 기존 구조. 최종 모바일 서비스 방향과 맞지만 현재 유료 API 예산이 제약이다. |
| 중앙 서버 + 사용자별 개인 구독 | 검토했다. 사용자별 인증과 실행 격리, 제공업체별 지원 범위가 필요하므로 초기 채택안으로 확정하지 않았다. |
| 개인 PC 서버 + 데스크톱 클라이언트만 제공 | 초기에도 모바일 이용을 원하므로 선택하지 않았다. |
| 개인 PC 서버 + 모바일 클라이언트 | 초기 배포 방향으로 합의했다. 외부 접속을 실제 확인하고 기존 웹 재사용을 우선 검토한다. |
| 휴대폰 내부에서 AI CLI 직접 실행 | 공식 지원과 안정적인 지속 실행을 전제할 수 없어 초기 방향으로 선택하지 않았다. |

사용자별 구독을 중앙 서버에서 사용한다면 논리적인 사용자별 인증 상태는 필요하지만, 사용자 수만큼 물리 서버나 상시 실행 CLI가 필요하다는 뜻은 아니다. 실행 작업을 제한된 동시 처리량으로 처리하는 방법을 논의했으나 동시 처리량·대기 허용 정책은 합의하지 않았다.

## 시스템 경계

검토 대상 시스템은 개인 PC의 분석 서버와 모바일 클라이언트를 포함한다. 주 액터는 사용자이며 AI 서비스와 금융정보 제공 시스템 등은 실제 외부 시스템이다. 개인 PC의 분석 처리기와 저장소는 시스템 내부 요소다.

## 합의한 기능 요구사항

| ID | 요구사항 |
| --- | --- |
| FR-PM-001 | 사용자는 개인 PC에서 실행되는 분석 서버를 모바일에서 이용할 수 있어야 한다. |
| FR-PM-002 | 사용자는 집 밖의 모바일 데이터 및 다른 Wi-Fi에서도 개인 PC의 분석 서버에 접속할 수 있어야 한다. |
| FR-PM-003 | 개인 PC가 꺼지거나 연결되지 않아도 사용자는 모바일에 이미 받아둔 분석 결과를 조회할 수 있어야 한다. |
| FR-PM-004 | 새 분석과 조건 감시는 개인 PC가 켜져 있고 필요한 서비스에 연결되어 있을 때 제공한다. PC가 꺼진 동안에는 새 분석과 조건 감시를 수행하지 않는다. |
| FR-PM-005 | 모바일에서 개인 PC의 분석 서버에 연결할 수 없으면 이미 받아둔 결과 조회만 허용하고, 새 분석 요청과 설정 변경은 차단한다. 오프라인 요청을 보관했다가 재연결 후 자동 실행하지 않는다. |
| FR-PM-006 | 초기 설치·이용 검증 대상 모바일 플랫폼은 Android로 한다. |

모바일에 받지 않은 과거 결과를 PC가 꺼진 동안에도 조회할 수 있다고 보장하지 않는다. 초기 오프라인 조회를 위해 중앙 서버에 분석 결과를 보관하는 구조는 요구하지 않는다.

## AI 이용 방향과 기존 모델의 검토 지점

개인 AI 구독을 활용하는 실행 방식을 검토하며, 초기 제공업체 범위를 좁히는 데 동의했다. 제공업체, 구독 연동 지원 범위와 실행 방식은 미정이다. 개인 구독이 모든 자동 분석이나 배포 방식에서 사용 가능하다고 전제하지 않는다.

기존 CONTEXT.md의 종목 분석은 모든 사용자에게 공통인 결과로 정의되어 있다. 개인 실행 결과의 소유·공유 범위는 아직 결정하지 않았으므로 기존 용어 정의를 변경하지 않는다.

AI CLI는 개인 PC에서 실행하더라도 모델 추론까지 PC에서 수행한다는 의미는 아니다. 외부 AI 서비스 이용 한도와 인증 갱신·재연결 처리는 남는다. 요청마다 한 인증 상태를 로그아웃·로그인하며 교체하는 방식은 채택하지 않았다.

논의 중 확인한 공식 자료는 아래와 같다. 원격 CLI 로그인 가능성과 제삼자 앱이 구독을 이용해 서비스를 제공할 수 있다는 판단은 구분한다. 배포 방식과 자동 분석에 대한 실제 지원 범위는 구현 전에 다시 확인한다.

- [Codex 인증](https://learn.chatgpt.com/docs/auth): 구독 로그인과 원격·비대화형 환경 인증 안내.
- [Sign in with ChatGPT 연동](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt): 구독 사용 권한 연동 경로와 원격 호스팅 앱의 접근 권한 신청 안내. 반드시 CLI를 경유하는 구조는 아니다.
- [Claude Code 이용 안내](https://code.claude.com/docs/en/legal-and-compliance): 정식 바이너리 호스팅 조건과 제삼자 앱의 구독 인증 중계 제한을 구분한다.
- [Gemini CLI 인증](https://geminicli.com/docs/get-started/authentication/) 및 [이용 안내](https://geminicli.com/docs/resources/tos-privacy/): 저장된 인증의 비대화형 실행과, CLI 인증을 이용한 서비스 직접 접근 제한을 구분한다.

## 외부 접속 가능성 검증 기록

2026-10-18 대화에서 사용자는 Android 폰과 PC를 Tailscale로 연결하고, Serve가 제공한 HTTPS 주소의 `/health`에서 `{"status":"ok"}` 응답을 확인했다고 보고했다. 이는 PC 서버와 모바일 사이의 HTTP 요청·응답 도달 가능성을 확인한 결과다. 에이전트가 폰의 Wi-Fi 비활성화나 모바일 데이터 사용 상태를 직접 확인하지는 않았으므로, 외부 네트워크 재검증 시 해당 조건을 명시적으로 확인한다.

검증 경로는 다음과 같다. 이는 현재 시험 구성이며 최종 외부 접속 기술을 확정하는 결정은 아니다.

```text
Android 브라우저 → Tailscale Serve의 HTTPS 주소 → PC의 127.0.0.1:8000/health
```

- PC에서 기존 FastAPI 서버를 실행하고 `tailscale serve http://127.0.0.1:8000`으로 연결한다.
- PC와 폰은 동일한 개인 Tailscale 네트워크에 연결한다.
- Serve용 HTTPS 인증서를 활성화하고, 일반 인터넷 공개용 Funnel은 필요하지 않다고 안내했다.
- 폰의 Wi-Fi를 끄고 모바일 데이터를 켠 상태에서 Serve 주소의 `/health`를 열어 같은 응답을 확인하는 것이 외부 접속 성공 기준이다.
- 분석 결과 조회, 서비스 로그인, OAuth 왕복, 오프라인 조회와 CLI 기반 분석 실행까지 검증한 것은 아니다.

참고: [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve). 시험에 사용한 개인 기기 주소와 인증 정보는 문서에 보관하지 않는다.

## 기존 웹 활용과 후속 검증 후보

현재 React 웹의 로그인, 관심종목, 분석 결과·이력, 수동 분석, 알림 조건과 알림 연결 화면을 재사용할 수 있다. 모바일 반응형 스타일도 존재한다. 우선 폰 브라우저에서 기존 웹을 확인하고 Android 설치형 앱으로 패키징하는 방향을 제안했으나, 패키징 기술은 아직 확정하지 않았다.

Capacitor는 기존 웹을 Android 앱으로 패키징할 수 있는 후보이며, 현재 저장소의 구현 범위에는 포함되지 않는다. 웹 재사용이 그대로 Android 설치·인증·오프라인 지원 완료를 뜻하지 않는다.

- 기존 웹은 같은 출처의 쿠키 인증과 상대 API 주소를 사용한다. 외부 HTTPS 웹 이용 시 웹 주소·쿠키·카카오 콜백 설정을 확인해야 한다.
- 앱 안에 웹을 패키징하면 개인 PC의 서버 주소 설정과 앱에서의 인증·로그인 복귀를 별도로 검토해야 한다.
- 모바일 결과 보관과 오프라인 변경 차단은 추가 작업이다.
- 개인 테스트는 스토어 정식 출시 이전에 Android 폰에 직접 설치해서 진행할 수 있다.

참고: [Capacitor](https://capacitorjs.com/docs), [Android 실기기 테스트](https://developer.android.com/studio/run/device).

## 미결정 사항

- 외부 접속과 PC·모바일 간 연결 인증 방식
- 모바일에 보관할 결과의 범위·기간, 최신성 표시와 기기 변경 시 처리
- 요청 전송 중 연결이 끊겨 처리 여부를 확인할 수 없는 경우의 표시와 재연결 후 상태 확인
- 초기 AI 제공업체와 공식적으로 지원되는 구독 연동 방식
- 개인 실행 결과의 소유·공유 범위
- 모바일 알림 전달 방식
- 중앙 서버 이전 시 계정·인증·분석 이력의 이전 정책

유스케이스 명세와 상세 설계는 후속 논의에서 작성한다. 본 문서는 전체 OOA 또는 구현 설계의 완료를 의미하지 않는다.
